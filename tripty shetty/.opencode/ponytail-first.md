# Ponytail first — no exceptions

Every task, every skill, every edit goes through the ponytail skill BEFORE anything else:

1. Load the `ponytail` skill first (current level applies; default: full).
2. Apply its ladder to the whole task — including deciding whether parts of the request need to exist at all.
3. Only after ponytail has shaped the approach, load/use any other skill or write code.
4. If another skill conflicts with ponytail, ponytail wins unless the user explicitly says "stop ponytail" / "normal mode".

This rule is not optional and not skill-dependent: refactors, bug fixes, new features, reviews, tests, docs — all routed through ponytail.
